## 4. Scope and Definitions

This amendment controls only historical signal-evidence authority and the
partition-safe creation of the Fold 1-2 entry manifest.

Definitions:

- **Frozen E3 entry:** one member of the original `full_stack`, `B_BASE`, SHORT
  entry set fixed before E5.
- **Contemporaneous evidence:** evidence persisted no later than the frozen
  entry's information cutoff and bound to that entry by an immutable identity
  and source hash.
- **Current-brain replay:** executing a present or later D3, RV2, TRRM, QMAE,
  EQM, ECON1, or final Aegis implementation against historical inputs.
- **Combined source:** the immutable, hash-bound E3 source containing records
  from Folds 1-4.
- **Blind exporter:** the non-interactive custodial process authorized in
  Section 12 to project Fold 1-2 records without exposing Fold 3-4 payloads.
- **Scientific pipeline:** the ordinary E5 Phase 1 and later analysis process,
  which is not authorized to open the combined source.
- **Essential field:** a field required for E5 identity, partition membership,
  temporal validity, direction, entry, score authority, mandatory label,
  horizon construction, cost, funding, or economic outcome.

## 5. Historical E3 Entry Authority

Rule `E5-A05-R001`: the historical E3 entry population remains frozen and
authoritative. No historical E3 entry may be rescored, reselected, reranked,
regenerated, replaced, removed because the current brain disagrees,
supplemented with a new entry, or passed through the current brain to determine
historical eligibility.

Rule `E5-A05-R002`: the authority order for evidence attached to a historical
entry is:

1. the frozen E3 entry record itself;
2. immutable contemporaneous artifacts explicitly referenced by that record;
3. contemporaneous metadata that existed before E5 opened and is joined by an
   immutable identity and verified hash.

Later source code, current model output, current operational state, or a
similar record has no historical evidence authority.

Rule `E5-A05-R003`: D3, RV2, TRRM, QMAE, EQM, ECON1, and final Aegis outputs are
authoritative historical evidence only when the exact output was persisted
contemporaneously and links to the frozen entry through an immutable identity
and verified source hash. Mere availability of current code with the same
component name is insufficient.

## 6. Prohibition on Retrospective Reconstruction

Rule `E5-A05-R004`: no process may replay a current or later implementation of
D3, RV2, TRRM, QMAE, EQM, ECON1, or final Aegis decision logic to reconstruct
missing historical component evidence. An attempted replay fails with
`E5_HISTORICAL_COMPONENT_REPLAY_PROHIBITED` before component execution.

Rule `E5-A05-R005`: no process may infer a missing component output from an
aggregate E3 score, final label, downstream outcome, later implementation,
similar row, model prediction, or economic result. An aggregate score is not a
component-level substitute. Imputation, synthesis, and decomposition fail with
`E5_HISTORICAL_COMPONENT_IMPUTATION_PROHIBITED`.

These prohibitions do not alter the frozen aggregate `score`. The exact
persisted score remains authoritative where required by E5.

## 7. Historical Evidence Availability States

Rule `E5-A05-R006`: each modern component evidence slot in a historical
evidence envelope must contain either authoritative evidence and source
provenance or exactly one of these canonical states:

| State | Meaning | Scientific interpretation |
|---|---|---|
| `AVAILABLE_VALID` | authoritative contemporaneous evidence exists and validates | use only where existing governance requires the field |
| `NOT_AVAILABLE_HISTORICAL_NOT_PERSISTED` | the component evidence was not persisted contemporaneously | unavailable; not zero, negative, rejection, or failed gate |
| `INVALID_HISTORICAL_EVIDENCE` | a purported value violates its frozen type or semantic contract | invalid; row handling follows the field's existing authority |
| `HISTORICAL_EVIDENCE_VALIDATION_FAILED` | identity, hash, provenance, or temporal validation failed | failed validation; do not use the evidence |
| `HISTORICAL_COMPONENT_REJECTED` | authoritative contemporaneous evidence explicitly records component rejection | rejection only; never interchangeable with missingness |
| `HISTORICAL_SOURCE_ARTIFACT_UNAVAILABLE` | an explicitly referenced immutable source artifact cannot be obtained or verified | unavailable source; do not reconstruct |

Rule `E5-A05-R007`: only
`NOT_AVAILABLE_HISTORICAL_NOT_PERSISTED` represents a component that was not
persisted. It does not change entry membership and is not a scientific
covariate unless an earlier authority explicitly requires that availability
state. It cannot populate an essential E5-R012 field.

Rule `E5-A05-R008`: invalid evidence, validation failure, component rejection,
and an unavailable referenced artifact remain distinct in schemas, artifacts,
counts, and failure propagation. No state may be silently converted to another.

## 8. Two-Lane Evidence Model

Rule `E5-A05-R009`: evidence is separated into two non-mergeable lanes.

**Lane A - Historical E5 lane**

- contains only the frozen E3 entries;
- uses only authoritative contemporaneous evidence;
- permits `NOT_AVAILABLE_HISTORICAL_NOT_PERSISTED` for nonessential modern
  component evidence;
- prohibits current-brain replay, rescoring, and reconstruction; and
- is the only lane eligible for the currently preregistered historical E5
  experiment.

**Lane B - Prospective current-brain lane**

- records D3, RV2, TRRM, QMAE, EQM, ECON1, and final Aegis evidence only for
  signals generated after a read-only observational exporter is implemented;
- may support Shadow, future live validation, or a separately governed future
  experiment;
- cannot enter, replace, supplement, validate, or reconstruct Lane A; and
- carries a distinct schema identity, artifact root, manifest, and run identity.

Rule `E5-A05-R010`: joins, unions, fallback reads, identity aliasing, or row
substitution between Lane A and Lane B are prohibited for E5. Lane B evidence
cannot be presented as historical evidence merely because field names match.

## 10. Fold 1-2 Manifest Authority

Rule `E5-A05-R013`: a new immutable, row-level Fold 1-2-only manifest is
authorized as a partitioned projection of the frozen combined E3 source. It is
not a new selection, population, score, or label artifact.

The projection must preserve exactly:

- source row membership for authorized Folds 1 and 2;
- frozen identity fields and values;
- score and strategy identity;
- label values or immutable label references when the applicable source
  contract carries them;
- source order among emitted Fold 1-2 records;
- timestamps, symbol, cycle, side, entry, horizon authority, and source
  references; and
- the source bytes and source hash as immutable provenance.

It may neither add nor remove a Fold 1-2 entry except by a deterministic hard
failure that leaves the output unsealed. It must never emit a Fold 3 or Fold 4
record.

Rule `E5-A05-R014`: the canonical scientific entry payload in the projection is
the existing Execution Specification field set:

```text
trade_id
symbol
fold
signal_timestamp
entry_timestamp
entry_price
side
score
strategy_id
```

Hash-bound source references and the component availability map are carried in
the projection's provenance envelope. Target labels remain governed by the
separate frozen target-label contract and may be linked only by immutable row
identity and hash. The exporter cannot recompute a label.

## 11. Authoritative Partition Selector

Rule `E5-A05-R015`: partition membership is selected only from the frozen
`fold` field persisted with each E3 signal record. Static repository schema
evidence locates it at `report.trades[].signal.fold`: `EconomicSignal.fold` is
defined in `src/aegis/training/econ.py:38-46`, and the immutable report is
serialized from `EconomicTrade.signal` in
`src/aegis/training/phase_e.py:1056-1066`. The existing frozen-entry adapter
reads `trade["signal"]["fold"]` in
`scripts/diagnostics/exit_excursion_d1a/experiment.py:141-177`. These static
references identify the persisted field; they do not authorize deriving fold
from another value or opening a scientific row in this task.

Accepted canonical values are integer `1` or string `F1` for Fold 1, integer
`2` or string `F2` for Fold 2, integer `3` or string `F3` for Fold 3, and
integer `4` or string `F4` for Fold 4. The exporter normalizes those values only
for comparison and records the original validated value in source provenance.
Only F1 and F2 are emitted.

Fold membership must not be derived from outcomes, scores, timestamps,
symbols, labels, present-day code, or any reconstructed field. Missing fold or
any value outside the four accepted forms fails with
`E5_AUTHORITATIVE_FOLD_SELECTOR_UNAVAILABLE`. No timestamp-based fallback is
authorized.

Rule `E5-A05-R016`: the exporter must apply the frozen experimental-arm
identity before projection: `scenario_id=B_BASE`, `strategy_id=full_stack`, and
`side=SHORT`. These are frozen source attributes, not newly evaluated gates.
An absent or conflicting attribute is an essential-field failure, not a reason
to infer membership.

## 12. Blind Mechanical Export Authorization

Rule `E5-A05-R017`: one deterministic, non-interactive blind mechanical
exporter is prospectively authorized solely to create the Fold 1-2 projection.
The custodial process may:

1. verify the expected physical SHA-256 of the combined frozen source before
   parsing records;
2. parse only the schema needed to locate records and the authoritative fold
   selector;
3. validate the frozen experimental-arm attributes;
4. copy the authorized Fold 1-2 fields and immutable source references;
5. validate schema, identity, uniqueness, and provenance;
6. compute hashes and non-sensitive integrity counts;
7. emit the Fold 1-2-only manifest and compact audit artifacts; and
8. resume from sealed non-payload checkpoints bound to identical dependencies.

The exporter must not display, log, return, sample, preview, summarize, rank,
or otherwise expose Fold 3-4 scientific fields. It must not calculate Fold 3-4
outcomes, statistics, comparisons, or counts for downstream scientific use. It
must not export Fold 3-4 rows, accept arbitrary queries, or expose the combined
source to the Phase 1 process.

Rule `E5-A05-R018`: Fold 3-4 records may be handled internally only to the
minimum extent required to read their authoritative fold selector and skip the
record. No other field from a skipped record may be deserialized into an
exported, logged, exception, tracing, metrics, preview, or debugging channel.
Any prohibited payload must be replaced by a non-sensitive failure code and
the export must fail closed.

Rule `E5-A05-R019`: exporter exception handling must use fixed error templates
containing code, source artifact identity, and non-sensitive record ordinal
only. Raw records, field values, serialized exceptions from parsers, stack
locals, and payload fragments cannot leave the isolated exporter boundary.

## 13. Clean-Room Boundary

Rule `E5-A05-R020`: the blind exporter and the E5 Phase 1 scientific pipeline
are separate processes with separate allowlists.

The Phase 1 process may receive only:

- the approved Fold 1-2 manifest;
- its schema and provenance manifest;
- source hash references;
- the component availability states in Section 7; and
- non-sensitive validation and audit results.

The Phase 1 process must not receive the combined Fold 1-4 source, Fold 3-4
rows, Fold 3-4 scientific summaries, prohibited row counts, parser traces, or
debugging output containing skipped payloads. After export, the combined
source path is denied to the normal Phase 1 process. An attempted open fails
with `E5_PHASE1_COMBINED_SOURCE_ACCESS_PROHIBITED` before any bytes are returned.

Rule `E5-A05-R021`: the Fold 1-2 output root is allowlisted to Phase 1 and the
combined-source root is allowlisted only to the isolated blind-exporter
executable identity. Symlink traversal, inherited file descriptors, temporary
payload files, core dumps, and broad read permissions that cross this boundary
are prohibited.

## 14. Deterministic Export Contract

Rule `E5-A05-R022`: identical combined-source bytes, expected source hash,
selector contract, exporter commit, and configuration hash must produce a
byte-identical Fold 1-2 manifest and audit manifest.

The output record order is the relative order of authorized Fold 1-2 records in
the immutable combined source. Source ordering is not changed. Serialization
uses the deterministic JSON or JSONL rules already frozen by the Execution
Specification. Audit timestamps are non-scientific metadata excluded from
scientific artifact identity and byte-identity comparison; a deterministic
scientific manifest contains no wall-clock timestamp.

Rule `E5-A05-R023`: an interrupted export may resume only from a sealed
checkpoint containing source SHA-256, source ordinal, rolling output SHA-256,
exporter commit, schema version, configuration hash, and permitted-field-list
hash. Resume validates every dependency and reconstructs the same final bytes.
A mismatch discards no source record and produces no sealed output.

Rule `E5-A05-R024`: the exporter rejects source hash mismatch, unknown schema,
duplicate identity, conflicting identity, missing selector, unknown partition,
unauthorized output field, nondeterministic ordering, incomplete provenance,
and any Fold 3-4 emission. No partial output is promoted after a failure.

## 15. Exporter Audit Contract

Rule `E5-A05-R025`: every attempted export produces a compact, non-scientific
audit artifact with these mandatory fields:

- exporter schema version;
- combined source file identity and relative path alias;
- expected and observed source SHA-256;
- source authority reference;
- partition-selector authority;
- exporter source-code commit;
- configuration SHA-256;
- exact permitted-field list and its SHA-256;
- Fold 1-2 output row count;
- duplicate count;
- rejected-row count and non-sensitive failure-code counts;
- output path and SHA-256 when sealed;
- deterministic ordering declaration;
- start and end timestamps as non-scientific audit metadata;
- deterministic invocation identity;
- interrupted/resumed status and checkpoint hashes;
- confirmation that no Fold 3-4 payload was emitted;
- confirmation that no scientific statistic was calculated;
- confirmation that the downstream process never opened the combined source;
- confirmation that semi-blind and lockbox resources were not accessed; and
- final status `PASS`, `FAIL`, or `BLOCKED`.

No audit artifact may include a prohibited record sample, Fold 3-4 field value,
Fold 3-4 payload count, scientific summary, outcome, score distribution, or
cross-fold comparison.

## 16. Access Semantics

This narrow authorization does not authorize Discovery on Fold 3-4, does not

audit record, and leave lockbox state unchanged.
